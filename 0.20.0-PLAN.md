# Quick Menu 0.20.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Quick Menu 0.20.0: every bug and ruling from Josh's three 0.19.0 test phases, so a blind PF1 player hears the right result of every command, never loses one, and never gets silence.

**Architecture:** The module is plain ES modules loaded by Foundry (no bundler). Pure logic lives in small modules under `scripts/` with node tests in `test/*.test.mjs`; the Foundry-facing glue (hooks, `game`, DOM) lives in `scripts/module.js`, `ActionExecutor.js`, `QuickMenuManager.js`, `KeyboardHandler.js` and `TTSManager.js`. Every task puts new rules into a pure function with a test first, then wires it into the glue. One shared "reader" slot for chat cards becomes one reader per command; "Card posted." becomes a composed use line; card notes are read from the card HTML.

**Tech Stack:** JavaScript ES2022 modules, Foundry VTT 13.351 (f1-f3, f5) and 14.370 (f4), PF1 11.11 release (f1-f3) and PF1 master (f4), node 22 for tests (`node test/<file>.test.mjs`, no package.json, no framework: each file is a script with `assert/strict` and a local `t()`), Chrome `speechSynthesis`.

**Spec:** `0.20.0-SCOPE.md` (repo root; `docs/` is gitignored here). Test numbers (1.2, 10.16, ...) are Josh's and match `TESTING-0.19.0-FINDINGS.md`.

## Global Constraints

- Both PF1 builds must keep working: PF1 11.11 on Foundry 13 (f1-f3) and PF1 master on Foundry 14 (f4). `item.use()` refusals are `{err, code}` on v13 and `{error, get code()}` on v14; `UseOutcome.useOutcome` already reads both.
- Container contents: PF1 11.11 keeps them in the container's `system.items`; PF1 master keeps them as actor items with `flags.pf1.container = <containerId>`. Read both everywhere.
- Never speak nothing: every command ends in a spoken confirmation or a spoken failure (`_fail`), never silence.
- Never cancel a speech line Chrome has not started (`SpeechQueue`), in any path.
- Spoken strings are Josh's: short, result first, no "Card posted.", no "Plus notes".
- Codes: a fixed core code (skills, saves, checks) is identical on every character and can never be overridden by an alias; a remembered code never records an alias.
- Menu entry `label` is used for command codes (`stableKey`); never change `label` for speech. Use `menuLabel`.
- Tests: `node test/<name>.test.mjs` prints `N assertions passed.` and exits 0. Run every file before each commit: `for f in test/*.test.mjs; do node "$f" >/dev/null || { echo "FAIL $f"; break; }; done`.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Stage named files only (never `git add -A`). Branch: `v14-accessibility`.
- Live check on f4 first (port 30003, world `03-shackletastic`, Ser Toche `mgOg5Dtln6mGStwP` has a Bag of Holding `QGN970psKmL7b8A6`), then f1. Deploy procedure is in Task 24.

A message is taken only if `isOwn(message) && match(message)`; otherwise the reader stays armed. If `waitMs > 0` and nothing has matched after `waitMs`, `onWaiting()` is called once.
